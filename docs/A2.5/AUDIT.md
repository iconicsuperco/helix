# A2.5 Repository Audit

Date: 2026-07-18

## Summary

Helix is a compact research repository with A1 tokenizer and A2 transformer code in place.
The core tokenizer and transformer behavior is covered by focused unit tests. The main
gaps before A2.5 were engineering foundations: missing project metadata, missing quality
tooling, missing CI, local cache files in the working tree, duplicated configuration and
logging helpers, and thin documentation.

## Findings

| Area | Finding | Proposed fix | Risk |
|---|---|---|---|
| Generated artifacts | `.mypy_cache/`, `.pytest_cache/`, `.DS_Store`, and `docs/.DS_Store` existed in the working tree. | Add `.gitignore` coverage and remove local cache/OS files. | Low; these files are not source. |
| Generated research outputs | `research/tokenizer/artifacts/tokenizer.json` and `tokenizer_card.md` are generated by A1 but tracked. | Keep the current artifact tracked because tests and A2 depend on it; ignore future generated variants unless explicitly promoted. | Medium; regenerated tokenizers can silently change compatibility if promoted without an ADR. |
| Dataset outputs | `datasets/processed/tokenizer-training/*.txt` are generated from raw corpus data and tracked; raw Moby Dick data is local/untracked. | Keep current processed split and manifest as the A1 baseline; ignore raw datasets by default. | Medium; contributors need the manifest and source instructions to regenerate from raw data. |
| Project metadata | No `pyproject.toml` existed, so dependencies and editable install were undefined. | Add PEP 517 packaging metadata and dev/test/quality dependency groups. | Low; install behavior becomes explicit. |
| Quality tooling | Ruff, MyPy, PyTest, and pre-commit were not configured. | Configure tools in `pyproject.toml` and add `.pre-commit-config.yaml`. | Low; future changes may need formatting or typing fixes. |
| CI | No GitHub Actions workflow existed. | Add push/PR workflow that installs the project and runs Ruff, MyPy, and PyTest. | Low; first remote run depends on PyTorch wheel availability for the selected Python version. |
| Duplicated utilities | YAML loading, repository path resolution, and JSON log formatting were repeated across research scripts. | Add `helix/common/` with shared config, paths, logging, seed, exception, and type helpers; route tokenizer script logging through the shared logger. | Low; existing A1/A2 logic remains unchanged. |
| Inconsistent imports | Tests inserted `research/model` and `research/tokenizer` directly into `sys.path`; transformer imported `config` as a top-level module. | Add package initializers, centralize pytest path setup, and make transformer config import package-compatible while preserving direct import fallback. | Low; this is import compatibility only. |
| Inconsistent documentation layout | `HELIX_A2_TRANSFORMER_SPEC.md` lived at the repository root while the roadmap, TDD, and A1 spec lived under `docs/architecture/`. | Move the A2 spec into `docs/architecture/` with the rest of the architecture documents. | Low; documentation path changes only. |
| Documentation | `README.md` was deleted in the worktree and there was no contribution guide or project status file. | Recreate README, add `CONTRIBUTING.md`, and add `docs/PROJECT_STATUS.md`. | Low; docs now reflect current setup and quality gates. |
| Dead code | No obvious unused Python files were found. Existing scripts are tied to A1 tokenizer reproducibility. | Keep files in place. | Low. |
| Technical debt | Placeholder corpus is intentionally narrow; tokenizer and processed split are not backed by a dataset versioning tool; common config loader is new and not yet used by every legacy module. | Track in project status and address in A3 or a follow-up infrastructure pass. | Medium; research reproducibility depends on disciplined artifact promotion. |

## Assumptions

- A1 tokenizer and A2 transformer APIs must remain backward compatible.
- The tracked tokenizer artifact is an intentional baseline, not disposable build output.
- Raw datasets should not be committed; manifests should describe how to recover them.
- CI should prioritize the Python research stack and stay independent of future platform code.
- A3 will integrate the common config, logging, paths, and seed helpers more deeply as the
  training pipeline is introduced.
